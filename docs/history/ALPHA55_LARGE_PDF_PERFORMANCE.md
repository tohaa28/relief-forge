# Alpha.55 — ускорение ручного редактирования составных PDF (2026-11-18)

## Проверенный пример
Файл пользователя `gerb2.pdf`: PDF 1.7, CorelDRAW 2025 (Corel PDF Engine 26.2.0.170), одна страница, 1544964 байт, 374.483×217.486 pt. PyMuPDF `page.get_drawings()` вернул **1 составной объект**, 7545 кубических сегментов `c` и 2 `l`; растровых объектов `get_images()` не обнаружено. Это воспроизводимая причина плохой масштабируемости всех операций, считавших «один объект» малым. Исходный PDF остаётся только в файлах разговора; не коммитить пользовательские исходники в публичный GitHub.

## Корень прежней деградации
Alpha.54 уже не запускала Rust/full-document diagnosis при правке узла, но `pointermove` повторно вызывал `moveCurveNode`/`moveCurveHandle` на полном составном объекте и `render()`. Последний выполнял `#geometry.replaceChildren()`, `#markers.replaceChildren()`, `#paths.replaceChildren()`, сериализацию всех кривых и создание тысяч SVG-якорей в выбранной фигуре. Даже `requestAnimationFrame` ограничивал число полных пересозданий, а не стоимость каждого кадра.

## Реализованное решение
1. `web/manual-edit-performance.js`: `buildAnchorIndex` создаёт пространственные корзины один раз для конкретного неизменяемого пути; `nearbyAnchors` выбирает максимум 240 ближайших якорей вокруг курсора (плюс явно выбранный), с безопасным fallback для крайне малого/сплющенного изображения при масштабировании. Остальные узлы не стираются из документа: их просто не требуется рисовать одновременно. Переключение курсора/выделения и новый снимок пути переиспользуют/обновляют кэш `WeakMap`.
2. `createLiveCurvePatch` сохраняет лишь два соседних нативных участка около выбранного узла; `drawLiveCurvePatch` двигает только их собственные контрольные точки, отображая миниатюрный бирюзовый SVG `path`. Для гладких/симметричных ручек применён контроль противоположной касательной. Исходные `path.commands`, `artwork` и `points` остаются **без изменений** на протяжении всех `pointermove`.
3. `app.js`: новый лёгкий слой `manual-live-patch` обновляется через `requestAnimationFrame` без вызова `render()`; выбранный глиф переносится SVG-transform. Прежние 40 mousemove → 40 full render заменены на единственный DOM `path.setAttribute('d',...) ` на кадр, ограниченный двумя сегментами. Точная геометрия пересчитывается существующими проверенными функциями **один раз при pointerup**, что сохраняет свойства EPS/CorelDRAW и Undo.
4. Существующая alpha54 локальная повторная проверка узлов остаётся только после фиксации правки, полный цикл импорта/диагностики и перестроения ПОСЛЕ — после выхода из узлового режима. При аварии/отмене прежние маркеры не пропадают.

## Контроль и ограничения
- `tests/alpha55-manual-performance.test.mjs`: 7545 C, не более 240 SVG-узлов в локальном радиусе, постоянный размер мини-патча даже после 500 движений, исходные команды не мутируются, сверхкрупный zoom-out не вызывает обход миллионов пустых ячеек.
- `scripts/browser-alpha55-heavy-edit.mjs`: Chromium + свежий Rust WASM, **синтетический** один объект с 2300 C, 40 перемещений реального мышиного курсора; MutationObserver на `#geometry` проверяет **0** global childList пересозданий до mouseup; после фиксации локальная диагностика и Undo.
- Полный тестовый набор EPS, PDF, Union, CNC, импорт и экспорт должен проходить без исключений. **Не утверждать live-публикацию, пока GitHub CI и Pages не подтвердятся.**
- Более глубокий F056-проект: инкрементальный пространственный индекс сегментов для сокращения чтения всех nativeParts после каждого mouseup. В alpha55 геометрия точно пересоздаётся один раз на pointerup, но **не** во время движения. Не заявлять, что O(N) commit исчез полностью.
- Исходная alpha54 `5842658972419b801aca88d3b1f25e472a384e64` — точка отката; новая feature-ветка `feature/alpha55-incremental-node-drag-viewport` и PR #84.
