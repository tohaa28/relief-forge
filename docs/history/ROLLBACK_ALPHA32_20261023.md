# Откат Relief Forge до 0.2.0-alpha.32 — 23.10.2026

## Запрос и контрольные точки
- Пользователь прямо запросил возврат к версии **0.2.0-alpha.32**.
- Исходная alpha.32: `4ad8efd1801be16d4c37472fda4989f9e3afbf06` (merge PR #38); дерево исходного Git `6cd82072293720fb5810d669de8db9cd8b48b36a`.
- Состояние, снятое перед откатом: **0.2.0-alpha.35**, коммит `bb56f9b11976fd75199b3b16f0f377be3df5bc18`.
- Полный резервный указатель: ветка `archive/alpha35-before-alpha32-rollback-20261023`. Её не перемещать при откате; поздние алгоритмы, тесты, методы и история доступны через неё.

## Использованный способ
Создать новый commit на основе `main`, заменив файловое дерево на дерево alpha.32 и возвращая только:
`AGENTS.md`, `HANDOFF.md`, `docs/DEVELOPMENT_LOG.md`, `docs/FEATURE_MATRIX.md`,
`docs/NEXT_CHAT_START.md`, файлы `docs/history/*` (журнал решений, failures, протокол),
`logs/actions.jsonl` как **современную неизменённую историю**. Дополнить их датированной записью об откате.
Не выполнять force-push и не переписывать Git history.

Таким образом, `src/`, `web/`, `Cargo.*`, `package*.json`, `tests/`, `.github/workflows/pages.yml`, исполняемые скрипты и статические файлы сайта берутся **байт-в-байт** из merge alpha.32. Файлы, введённые в alpha.33–35, не остаются в исполняемой версии. При проверке сравнить SHA всех файлов приложения с контрольной точкой.

## Ограничения и сознательно отменённые изменения
- Это не новый исправляющий релиз и не лечит дефект F-028; alpha.35-ограничение роста узлов и проверка EPS against AFTER откатываются.
- Убираются исправления ложных открытых контуров и топологических защит из alpha.34, UI и имени файла из alpha.35.
- Возвращается рабочий процесс GitHub Actions, существовавший на alpha.32. Он не выполнял позже введённый Chromium browser smoke; нельзя выдавать его тесты за браузерные.
- Внешние файлы пользователя EPS/CDR/PDF не записываются и не удаляются.
- Другие репозитории не меняются.

## Отвергнутые варианты
- Простое изменение отображаемой версии на alpha.32 при исходниках alpha.35: не настоящий откат.
- `git reset --hard`/force-push main к старому SHA: скрывает более позднюю историю и опасен для разработчиков.
- Смешение позднего алгоритма Union или новых UI-модулей с alpha.32: непредсказуемо и не является воспроизведением версии.
- Удаление архивных записей ошибок и неуспешных CI: нарушает требование воспроизводимости.
