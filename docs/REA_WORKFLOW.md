# Исследование ArtCAM через REA + Ghidra

Цель: наблюдаемое поведение и подтверждённая семантика лечения векторов. Наличие запущенного ArtCAM не даёт облачной сессии доступ к процессу Windows. Ghidra GUI и headless-provider REA — разные поверхности.

## Локальный сбор

Требуются установленные REA, подходящий Node.js, Ghidra и полный JDK. Настройки берутся из реальных путей машины, не угадываются. Официальные инструкции и границы версий: `docs/SOURCES.md`. Скрипт не устанавливает ПО и не меняет регистрацию MCP.

```powershell
.\scripts\Collect-ArtCAM.ps1
```

Скрипт найдёт единственный процесс ArtCAM и сохранит его идентификатор, заголовок, путь EXE, версию, SHA256 и результаты doctor/providers. Если процессов несколько — указать EXE явно.

```powershell
.\scripts\Collect-ArtCAM.ps1 -BinaryPath 'C:\actual\ArtCAM.exe' -GhidraDirectory 'C:\actual\ghidra' -JdkDirectory 'C:\actual\jdk' -InspectBinary
```

`-InspectBinary` включает headless-импорт и начальный поиск строк. Для большого EXE это может занять несколько минут. Реальные параметры команды проверяются по сохранённым `rea --version`, `rea --help`, `rea search --help`; при несовпадении версии остановиться и скорректировать вызовы. Ненулевой exit code записывается отдельно, вывод не трактуется как успех.

Результат: новая папка `evidence/private/artcam-<дата>/`. Ничего автоматически не загружается. Бинарники ArtCAM не копируются и не коммитятся. Данные этой папки не публиковать без отдельной проверки содержимого.

## Последовательность расследования

1. Сохранить версию, SHA и оригинальный выход provider diagnostics.
2. Зафиксировать экран Vector Doctor и все доступные параметры в реально открытом инструменте.
3. Строки интерфейса → подтверждённые адреса → xrefs → вызываемые функции. Не придумывать имена или адреса.
4. Сначала минимальные геометрические кейсы: два близких конца; три конца в одной точке; дубликат с другим стартом; касание; наложение; восьмёрка; маленькая петля на большом контуре.
5. Для каждого кейса: вход в мм, допуски, снимок до/после, экспорт результата, число контуров/узлов, площадь и направление, имена слоёв. Результат из документации и результат работающего ArtCAM хранить раздельно.
6. Rust-тест создаётся из подтверждённого наблюдения. Требуемые инварианты: не менять удалённую геометрию, сохранять масштаб, не соединять неоднозначную ветвь, корректно обрабатывать undo.

## Формат записи наблюдения

```json
{"case":"join-two-ends-001","target_sha256":"<observed>","tool":"Vector Doctor / Join","parameters":{"tolerance_mm":0.01},"input":"case-input.svg","output":"case-output.svg","observation":"<measured>","source":"runtime","confirmed":false}
```

`confirmed` становится true только после чтения результатов. Пока в проекте нет ни одного runtime-подтверждённого наблюдения ArtCAM.
