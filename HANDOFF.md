# Контрольная точка — 2026-10-22

## Задача пользователя

Разработать на Rust и опубликовать WASM функциональный аналог Autodesk ArtCAM 2018. Сначала базовые возможности, но полный набор лечения векторов обязателен. Пользователь открыл нужный инструмент в ArtCAM на Windows, просит использовать REA и Ghidra, работать эффективно и вести полный журнал. Разрешены новый GitHub-репозиторий и публикация. Пользователь готов предоставить доступ.

## Проект

Имя: Relief Forge, пакет `relief-forge`, версия `0.1.0-alpha.1`. Новый проект, **не продолжение VectorForge**. Аккаунт подключённого GitHub: `tohaa28`. Выбран репозиторий `relief-forge`; он ещё не создан, remote не настроен. GitHub-коннектор не предоставляет create-repository.

## Реальное состояние

1. Rust-код в src/lib.rs; dependency-free cdylib/rlib, packed f64 ABI.
2. UI web/: SVG DOM + JS; геометрические исправления выполняет исключительно WASM Worker. Без собранного engine.wasm кнопки расчёта отключены.
3. 15 содержательных Rust-тестов в tests/geometry.rs написаны, не запускались.
4. 7 JS-тестов проходят. Синтаксис JS проверен Node.js.
5. scripts/check-wasm.mjs проверяет скомпилированный модуль: ABI, пересечения, разбиение, петли, ошибки, повторные вызовы. Ещё не запускался.
6. Windows PowerShell-скрипты подготовлены, не запускались и не проверены PowerShell-парсером (нет pwsh).
7. Полная визуальная проверка браузера не выполнена. Никакая публичная страница не опубликована.
8. Скрипт Collect-ArtCAM.ps1 подготовлен по текущей официальной документации REA; фактического бинарного анализа не было.

## Проверенная среда и блокеры

- Это Linux-контейнер. cargo/rustc/rustup/rea и Ghidra не найдены.
- Инвентаризация компьютерных поверхностей: apps пусто; доступен Chrome без вкладок. Открытый ArtCAM на компьютере пользователя не виден.
- Проверка официального GitHub HTTPS из shell завершилась таймаутом 10 с. Доступ к первичным документам через web-search работает.
- `npm exec --offline --package=rea-agents -- rea --version` вернул ENOTCACHED. Не выдавать это за запуск REA.
- Дополнительно GitHub /new открыт через разрешённый браузерный fallback: перенаправление на страницу входа. Авторизованной браузерной сессии нет. Учётные данные не запрашивались и не вводились.
- GitHub профиль прочитан успешно. Доступа к созданию репозитория через существующие операции нет. Не использовать и не раскрывать токены.

## Следующий порядок

1. Получить ссылку на созданный пользователем `tohaa28/relief-forge` и подтвердить доступ к записи.
2. Загрузить текущую историю и файлы. Запустить CI; исправить любые ошибки Rust/ABI **до** заявления о готовой WASM-версии.
3. Проверить UI в браузере: пример → диагностика → удаление дубликатов → отмена → повтор → сохранить/открыть → экспорт/импорт SVG. Проверить отмену Worker и потерю указателя.
4. Опубликовать Pages после успешных тестов и проверить живой URL. Не выдавать предполагаемый URL за действующий.
5. Подключить REA/Ghidra на стороне Windows или получить локальный evidence-bundle от Collect-ArtCAM.ps1. Сначала doctor/providers/inspect, затем адреса строк → xrefs → реальные функции. GUI открытого инструмента сам по себе не даёт адреса функций.
6. Собрать поведенческие эталоны всех пунктов FEATURE_MATRIX. Для каждого вход, параметры, выход, версия ArtCAM, хеш бинарника и подтверждённое наблюдение.
7. Подключить подходящую готовую Rust-геометрию (kurbo + iOverlay / cavalier_contours после проверки), ввести исходные Безье/дуги и spatial index. Не наращивать нынешние O(n²) эвристики до промышленного ядра.

Полный набор лечения векторов **ещё не реализован**. Особенно важны кривые, касания, сложные петли, слои/группы и точное воспроизведение допусков. Сохранять эти ограничения при переносе чата.
